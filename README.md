# Redragon Keyboards G-Keys Remapper

Turn a Redragon keyboard's dedicated macro/G-keys into genuinely independent,
uniquely-identifiable key inputs (`F13`–`F22` by default) that Windows and
any application — Discord, OBS, streaming software, anything — can bind to
directly, with no side effects.

Built and tested against a **Redragon VISHNU K596RGB** (wired, VID `062A`
PID `8519`). Other Redragon keyboards with dedicated G-keys likely use a
similar vendor HID mechanism, though the exact byte values may differ — see
[Adapting this for a different keyboard](#adapting-this-for-a-different-keyboard)
below.

## The problem this solves

Redragon's own software lets you assign G-keys to things like "Keyboard
Keys", "Combo Key", or "Assign a string" — but none of these give you a
clean, independent key signal:

- **Keyboard Keys** mode just remaps the G-key to an ordinary key (e.g. F1),
  making it indistinguishable from your real F1 key.
- **Combo Key** mode (e.g. `Ctrl+Shift+F1`) sends the real, physical
  modifier keydown/keyup events — so `Ctrl` and `Shift` genuinely go down
  and up, which leaks into whatever app has focus and causes unintended
  side effects, and can't be reliably remapped away with tools like
  AutoHotkey since the underlying physical keys still fire.
- **Assign a string** mode types literal text into the focused window
  rather than sending a real keystroke at all.

None of these give you a key that behaves like a real, unique key — which
is what you want for something like binding Discord's "Toggle Mute" to a
G-key without accidentally triggering other shortcuts.

## How it works

The K596 (and likely other Redragon keyboards with G-keys) exposes a
**vendor-defined HID collection** in addition to its standard keyboard
collection. On the K596 this is usage page `0xFF19`, usage `0xFF19`. When a
G-key is set to "Assign a string" mode, pressing it fires a small HID report
on this vendor channel:

```
byte 0 = 0x08   (HID report ID)
byte 1 = 0x11   (event subtype -- observed constant for G-key events)
byte 2 = 0xC0 + (G-key number - 1)   e.g. G1=0xC0, G2=0xC1, ... G10=0xC9
```

This fires exactly once per physical press — not a down/up pair, and not
repeated while held — regardless of what action is assigned to the key
(as long as it isn't set to "Button Off", which suppresses it entirely).

Importantly, **this report is generated by the keyboard's own firmware**,
not by Redragon's PC software — it keeps firing correctly even with
Redragon's software fully closed (see
[Eliminating the placeholder-text side effect entirely](#eliminating-the-placeholder-text-side-effect-entirely)
below). The literal text that "Assign a string" types is a *separate*
thing, performed by Redragon's background software process watching for
this same signal — not the keyboard itself.

`k596_gkey_bridge.py` listens for the firmware-level HID report directly
via the Windows Raw Input API and, on each qualifying report, synthesizes a
clean, real keydown+keyup via `SendInput` — completely independent of
Redragon's software, and with none of the modifier-leak or text-injection
side effects described above.

## Requirements

- Windows 10/11
- Python 3.9+ (no third-party packages required — pure `ctypes`)
- Redragon's keyboard software, to configure the G-keys (one-time setup only
  — see below)

## Setup

### 1. Configure your G-keys in Redragon's software

Set every G-key you want to use to **"Assign a string"**, with any
one-character placeholder (it doesn't matter what — see step 2).

> **Don't leave it empty.** On the tested unit, an empty string silently
> reverts to whatever was previously saved instead of actually saving.

### 2. Close Redragon's software — this eliminates the placeholder-text side effect entirely

Once the G-keys are configured, **close Redragon's software completely**
(it usually runs as a background/tray process — check the system tray and
Task Manager, and end it there if closing the window alone leaves it
running). The G-key configuration is stored on the keyboard itself, so this
doesn't reset anything.

With the software closed:
- The vendor HID report keeps firing on every G-key press exactly as before
  (it's generated by the keyboard's firmware, not the PC software).
- The placeholder text is **no longer typed anywhere**, because that
  typing was being performed by Redragon's background software process,
  which is no longer running to do it.

This is the recommended setup — it's cleaner than trying to pick a
"harmless" placeholder character, since there's no side effect at all.

> **Trade-off:** closing Redragon's software also disables any other
> software-dependent features it provides (e.g. custom RGB lighting
> effects, on-the-fly profile switching). If you rely on those, you'll need
> to weigh that against the clean G-key behavior, or just relaunch the
> software briefly whenever you want to change those settings and close it
> again afterward. Onboard RGB effects stored on the keyboard itself
> typically keep working regardless.

### 3. Run the bridge

```
python k596_gkey_bridge.py
```

By default this runs quietly with no output. To watch it detect G-key
presses live (useful for confirming everything's wired up correctly):

```
python k596_gkey_bridge.py --debug
```

Press each G-key you've configured and confirm you see a line like:

```
[12:34:56.789] [Col05] G1 -> vk=0x7C
    [verify] GetAsyncKeyState after keydown: DOWN (OS registered it)
```

`DOWN (OS registered it)` confirms the key is actually reaching Windows —
if it says `NOT DOWN`, see [Troubleshooting](#troubleshooting).

Exit with `Ctrl+C` or by typing `q` and pressing Enter.

### 4. Bind the F-keys in your target application

G1 → F13, G2 → F14, ... G10 → F22 by default. In Discord's keybind
settings (or any other app), bind whatever action you want to the
corresponding F-key and press the G-key to record it.

### 5. (Optional) Run it automatically at login

```
powershell -ExecutionPolicy Bypass -File setup_k596_bridge_task.ps1
```

This registers a Windows Scheduled Task (`K596GKeyBridge`) that launches
the bridge silently at every login, with no console window. See
[setup_k596_bridge_task.ps1](#setup_k596_bridge_taskps1-reference) below
for options.

> If you also want Redragon's software to *never* start automatically
> either (so it stays fully closed after reboots too), check its own
> settings for a "launch at startup" option and disable it, or remove it
> from Windows' Startup Apps list (Settings → Apps → Startup).

## Files

### `k596_gkey_bridge.py`

The bridge itself. Run with `--help` to see all options:

| Flag | Default | Description |
|---|---|---|
| `--debug` | off | Print every detected event and verify injection via `GetAsyncKeyState`. |
| `--usage-page` | `0xFF19` | Vendor HID usage page to listen on. |
| `--usage` | `0xFF19` | Vendor HID usage to listen on. |
| `--report-id` | `0x08` | Expected report byte 0 for a G-key event. |
| `--subtype` | `0x11` | Expected report byte 1 for a G-key event. |
| `--base` | `0xC0` | Report byte 2 value corresponding to G1. |
| `--count` | `10` | Number of G-keys to recognize (G1..G\<count\>). |
| `--start-key` | `0x7C` (F13) | Virtual-key code to map G1 to; later G-keys increment from here. |
| `--debounce-ms` | `120` | Minimum time between accepted events for the same G-key. |
| `--hold-ms` | `20` | How long to hold the synthesized key down before releasing. |

Example — remap to Scroll Lock/Pause/etc. instead of F13+ (useful if your
target application's keybind picker doesn't support F13–F24; see
[Troubleshooting](#troubleshooting)):

```
python k596_gkey_bridge.py --start-key 0x91
```

### `setup_k596_bridge_task.ps1`

Registers/removes the Scheduled Task that runs the bridge at logon.

```
# Install (looks for k596_gkey_bridge.py next to this script by default)
powershell -ExecutionPolicy Bypass -File setup_k596_bridge_task.ps1

# Install with extra bridge arguments
powershell -ExecutionPolicy Bypass -File setup_k596_bridge_task.ps1 -ExtraArgs "--count 6 --start-key 0x91"

# Point at a script somewhere else
powershell -ExecutionPolicy Bypass -File setup_k596_bridge_task.ps1 -ScriptPath "C:\tools\k596_gkey_bridge.py"

# Start it immediately without logging out
Start-ScheduledTask -TaskName "K596GKeyBridge"

# Uninstall
powershell -ExecutionPolicy Bypass -File setup_k596_bridge_task.ps1 -Uninstall
```

The task is always registered to "Run with highest privileges." This only
takes effect if your Windows account is an Administrator, and for best
results run the installer itself from an elevated PowerShell (right-click →
"Run as administrator") — otherwise the elevated setting can be silently
ignored by Task Scheduler.

## Eliminating the placeholder-text side effect entirely

As covered in [Setup step 2](#2-close-redragons-software--this-eliminates-the-placeholder-text-side-effect-entirely),
the cleanest fix is simply closing Redragon's software after configuring
your G-keys once. The firmware-level HID signal this project depends on
keeps working; the software-driven text injection does not, because there's
no longer a process watching for the signal to type anything.

If for some reason you need to keep Redragon's software running (e.g. for
software-driven RGB effects), you can instead minimize the side effect by
using an inert one-character placeholder — a backtick (`` ` ``) or a digit
— instead of a space, since a literal space can trigger "scroll down" in
web views/browsers if a text field or webpage happens to be focused when
you press a G-key. This is a fallback, not a fix: some character will still
be typed into whatever has focus.

## Troubleshooting

**`GetAsyncKeyState` says `NOT DOWN` in `--debug` mode.**
`SendInput` isn't reaching the system. Check the console for a
`[!] SendInput failed` line with a `GetLastError` code — this usually means
a structural/environment issue rather than a permissions one. If you don't
see that line at all but still get `NOT DOWN`, try running as Administrator.

**A target app's keybind recorder won't pick up F13–F24 at all.**
Some applications' keybind *recorder* UI doesn't recognize extended
function keys, even though the app's underlying global-shortcut engine
might support them elsewhere — this varies by app and version. Work around
it with `--start-key`, e.g. `--start-key 0x91` (Scroll Lock) or
`--start-key 0x13` (Pause/Break), or any other virtual-key code for a key
you don't otherwise use. Since the physical G-key's own hardware never
generates that key/combo — only this script does, on purpose, once per
press — there's no risk of the usual side effects even if you pick an
ordinary key or a modifier combo.

**`SendInput` reaches the system but a specific elevated app doesn't see it.**
Windows blocks synthetic input from a non-elevated process reaching an
elevated one (UIPI). Run the bridge (or the scheduled task — see above)
elevated too.

**The page/app scrolls or a character appears when I press a G-key.**
That's the placeholder string side effect from Redragon's software — see
[Eliminating the placeholder-text side effect entirely](#eliminating-the-placeholder-text-side-effect-entirely)
above. Closing Redragon's software fully resolves this.

## Adapting this for a different keyboard

This was reverse-engineered against one specific K596RGB unit/firmware
revision by watching Windows Raw Input traffic while pressing G-keys
individually. If you have a different Redragon model (or a different
firmware revision of the same model), the report format may differ. To
find your own signature:

1. Set a couple of G-keys to "Assign a string" with distinct placeholder
   characters.
2. Run the bridge with `--debug` and press each key individually, with a
   pause between presses.
3. Look at the printed report bytes for a pattern — usually a fixed report
   ID and subtype byte, with a third byte that increments by one per G-key.
4. Pass your findings in via `--report-id`, `--subtype`, `--base`, and
   `--count`.
5. If your keyboard's vendor collection uses a different usage page/usage
   than `0xFF19`/`0xFF19`, you'll need to find that too — a tool like
   `hidapitester` against your device's HID report descriptor can help
   identify the right collection.
6. Test whether the report still fires with Redragon's software closed
   (see [step 2 above](#2-close-redragons-software--this-eliminates-the-placeholder-text-side-effect-entirely))
   — if so, you get the same clean, side-effect-free setup.

Pull requests adding confirmed report signatures for other Redragon models
are welcome — please note the exact model and VID/PID in your PR.
